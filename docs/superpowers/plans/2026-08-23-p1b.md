# P1b — טבלת ההשוואה והמרת המטבע

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.
> **מצב חי:** `docs/HANDOFF.md`. **המשימה הראשונה שאינה מסומנת היא נקודת ההמשך.**

**Goal:** שלוש הצעות משלוש מדינות, זו לצד זו, במטבע שהמטופל מבין — ובלי שהמערכת
תטען טענה שהיא לא יכולה לגבות.

**Architecture:** חיפוש השער הוא פונקציה טהורה מעל השורות שכבר במסד, כי צורת
האחסון מחייבת שילוש (ראו למטה) וזה בדיוק סוג הלוגיקה שנשברת בשקט. הטבלה מקבלת
ממיר מוכן ולא ניגשת למסד בעצמה.

**Tech Stack:** Next.js 16.2.11, React 19.2, Prisma 7.8 + Postgres, vitest (node).

**Spec:** `docs/superpowers/specs/2026-08-23-p1-design.md` — פרקים 5, 6.

## Global Constraints

- כל האילוצים מ-`2026-08-23-p1a.md` חלים כאן במלואם: `he.ts` מקור האמת,
  תבניות ולא פונקציות, `fileParallelism: false`, `docker start dentalcompare-db`.
- **`convert()` הוא לתצוגה בלבד.** הצעה נשמרת תמיד במטבע שהמרפאה נקבה בו.
  להמיר בשמירה זה להתחייב למחיר שהפלטפורמה לא שולטת בו (P0 §3.3).
- **`ExchangeRate` שמור בכיוון אחד**: הקרון בוחר את המטבע הראשון אלפביתית כבסיס
  ושומר רק `base → quote`. אין שורה הפוכה ואין שורה בין שני לא-בסיסים.
- **אין שינוי סכימה בעבודה הזו.**
- קומיט אחרי כל משימה.

## שני ממצאים שהתוכנית קיימת כדי לתקן

**1. השערים חד-כיווניים.** המרה מ-X ל-Y דורשת: X→base (היפוך) ואז base→Y.
מימוש שמניח שיש שורה ישירה יחזיר „אין שער” כמעט תמיד, ובשקט — המחיר פשוט
יוצג בלי המרה ואיש לא ידע שזה באג ולא החלטה.

**2. „ההצעה הזולה” עיוורת-מטבע.** `sortByPrice` ו-`cheapestDentistId`
משווים `amountMinor` גולמי. 5,000 ₺ נראים גדולים מ-4,000 € ולכן „יקרים יותר”,
בעוד שהם כעשירית המחיר. היום כל ההצעות בשקלים ולכן זה נכון במקרה. זה נשבר
ביום הראשון שבו הפיצ'ר עובד — כלומר בדיוק כשזה הכי חשוב.

### Task 1: חיפוש השער

**Files:** Create `src/lib/exchange.ts`, `src/lib/exchange.test.ts`

**Interfaces:**
- Produces: `type StoredRate = { base: string; quote: string; rate: number; fetchedAt: Date }`
- Produces: `findRate(rates: StoredRate[], from: string, to: string, now?: Date): { rate: number; fetchedAt: Date } | null`

- [x] **Step 1: הבדיקה הנכשלת** — `src/lib/exchange.test.ts`

```ts
import { describe, it, expect } from "vitest";
import { findRate } from "./exchange";

const fresh = new Date("2026-08-23T04:00:00Z");
const now = new Date("2026-08-23T10:00:00Z");
const rates = [
  { base: "EUR", quote: "ILS", rate: 4, fetchedAt: fresh },
  { base: "EUR", quote: "TRY", rate: 40, fetchedAt: fresh },
];

describe("findRate", () => {
  it("returns 1 for the same currency, with no stored row needed", () => {
    expect(findRate([], "ILS", "ILS", now)?.rate).toBe(1);
  });

  it("reads a stored row directly", () => {
    expect(findRate(rates, "EUR", "ILS", now)?.rate).toBe(4);
  });

  // The cron only ever stores base -> quote.
  it("inverts a stored row for the other direction", () => {
    expect(findRate(rates, "ILS", "EUR", now)?.rate).toBeCloseTo(0.25);
  });

  // Neither side is the base, so it goes ILS -> EUR -> TRY.
  it("triangulates through the base", () => {
    expect(findRate(rates, "ILS", "TRY", now)?.rate).toBeCloseTo(10);
  });

  it("has no rate for a currency it has never seen", () => {
    expect(findRate(rates, "ILS", "JPY", now)).toBeNull();
  });

  // A number presented as fact must not be two days old.
  it("refuses a rate older than the staleness window", () => {
    const old = [{ base: "EUR", quote: "ILS", rate: 4, fetchedAt: new Date("2026-08-20") }];
    expect(findRate(old, "EUR", "ILS", now)).toBeNull();
  });

  // A triangulated rate is only as fresh as its stalest leg.
  it("reports the older of the two legs when triangulating", () => {
    const mixed = [
      { base: "EUR", quote: "ILS", rate: 4, fetchedAt: new Date("2026-08-23T02:00:00Z") },
      { base: "EUR", quote: "TRY", rate: 40, fetchedAt: fresh },
    ];
    expect(findRate(mixed, "ILS", "TRY", now)?.fetchedAt).toEqual(
      new Date("2026-08-23T02:00:00Z"),
    );
  });
});
```
