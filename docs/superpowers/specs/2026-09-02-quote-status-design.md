# 0. הבעיה

`Quote` היום הוא בינארי: יש הצעה או אין. שני הדשבורדים (מטופל, מרפאה) יודעים
לומר "המרפאה ענתה" ותו לא. אין דרך למטופל לבחור עם איזו מרפאה הוא ממשיך, אין
דרך למרפאה לדעת אם המטופל בכלל בחר בה, ואין שום מעקב אחרי מה שקורה אחרי
שהמטופל בוחר — האם הוא בדרך, בטיפול, סיים.

זה סוגר את הפער: מחזור חיים מלא להצעה, משני הצדדים.

# 1. החלטות סגורות

התקבלו בליבון מול אדן ב-2026-09-02.

## 1.1 אישור הוא בלעדי בתוך בקשה אחת

מטופל מאשר הצעה אחת → **כל שאר ההצעות הפתוחות** (שטרם הוכרעו) באותה בקשה
נדחות אוטומטית, באותה טרנזקציה. אין מצב של "כמה הצעות מאושרות" בבקשה אחת —
המטופל טס לטיפול אחד, אצל מרפאה אחת.

## 1.2 דחייה עצמאית — לא רק כתוצאה מאישור אחרת

כפתור "דחה" נפרד לכל הצעה, בלתי תלוי באישור מרפאה אחרת. מטופל יכול לדחות
הצעה שלא מתאימה לו בלי לבחור עדיין באחרת. `Quote.rejectedAuto` מבדיל בין
"נדחה כי המטופל לחץ דחה" ל"נדחה כי אחרת אושרה" — לצורך אנליטיקה, לא לוגיקה.

## 1.3 מי מקדם סטטוס אחרי אישור

**המרפאה** מסמנת "הטיפול החל" ואז "מבקש אישור סיום" — היא היחידה שיודעת מתי
המטופל בפועל הגיע והטיפול הסתיים. **המטופל** הוא זה שמאשר סיום בפועל
(`COMPLETED`) — אישור חד-צדדי של המרפאה לא מספיק, כי היא זו שמרוויחה מלהראות
שיעור השלמה גבוה.

## 1.4 החלטות סופיות — אין ביטול ב-v1

אישור, דחייה, וכל מעבר סטטוס אחר הם **סופיים**. אין כפתור "בטל" ב-UI. מטופל
שטעה או שינה דעתו פונה לתמיכה (מחוץ להיקף האוטומציה כאן). זה מפשט את הלוגיקה
משמעותית — אין צורך "להחזיר" הצעות אחרות שנדחו אוטומטית.

## 1.5 מייל על כל מעבר משמעותי

בניגוד ל"דשבורד בלבד" — **כל** מעבר סטטוס שולח מייל לצד הרלוונטי, לפי אותו
דפוס retry-safe שכבר קיים (`Quote.patientNotifiedAt` + הקרון היומי). ראו §4.

# 2. המודל

## 2.1 `QuoteStatus`

```prisma
enum QuoteStatus {
  PENDING_DECISION     // הצעה קיימת, ממתינה להחלטת המטופל
  APPROVED              // המטופל אישר
  REJECTED               // נדחתה — מפורשות או אוטומטית
  IN_TREATMENT            // המרפאה סימנה שהטיפול החל
  COMPLETION_REQUESTED     // המרפאה ביקשה אישור סיום
  COMPLETED                 // המטופל אישר שהטיפול הסתיים
}
```

**עקרון מכריע:** `status` הוא **מקור האמת היחיד**. כל מסך, gate או פילטר שואל
את `status`, אף אחד לא גוזר אותו מחדש מצירוף של חותמות זמן. זו בדיוק המשפחה
של הבאג שחזרה פעמיים כבר במערכת הזו — `visibleSubscriptionFilter` ואז שער
הרישיון (`publicDentistWhere`) — שני מקומות שכל אחד ניסח מחדש את אותו תנאי,
ואחד מהם שכח עדכון. חותמות הזמן להלן הן **לתצוגה/audit בלבד**, אף פעם לא
לתנאי if.

**אין מצב "אין Quote" ב-enum** — כשאין עדיין `Quote` בשורה, המשמעות היא "נשלח,
טרם התקבלה הצעה" (המצב הבינארי הקיים היום, `RequestDentist.emailSent`). ה-enum
מתחיל להתקיים רק מרגע שיש `Quote`.

## 2.2 תוספות ל-`Quote`

```prisma
model Quote {
  // ...קיים...
  status                 QuoteStatus @default(PENDING_DECISION)
  decidedAt               DateTime?   // מתי אושרה/נדחתה
  rejectedAuto             Boolean    @default(false)
  treatmentStartedAt        DateTime?
  completionRequestedAt      DateTime?
  completedAt                 DateTime?

  // חותמות "נשלח מייל" — אחת לכל מעבר, אותו דפוס כמו patientNotifiedAt
  // הקיים. נשארות null עד שהשליחה הצליחה; קרון-retry קיים כבר מטפל ב-
  // patientNotifiedAt ומורחב לכסות גם את אלה (§4).
  decisionNotifiedAt          DateTime? // מייל למרפאה על אישור/דחייה
  treatmentStartedNotifiedAt   DateTime? // מייל למטופל שהטיפול החל
  completionRequestedNotifiedAt DateTime? // מייל למטופל לאשר סיום
  completedNotifiedAt            DateTime? // מייל למרפאה שהמטופל אישר סיום
}
```

מיגרציה אחת, אדיטיבית, בלי backfill — כל שורת `Quote` קיימת מקבלת
`PENDING_DECISION` כברירת מחדל, שזו בדיוק המשמעות הנכונה של הצעה קיימת שאיש
עדיין לא הכריע לגביה.

# 3. מעברי הסטטוס

## 3.1 מטופל מאשר הצעה

**קלט:** `requestDentistId` (מזהה השורה שאליה שייכת ה-`Quote`).
**מאמת:** המשתמש המחובר הוא בעל ה-`Request` (`request.userId === currentUser.id`).

בטרנזקציית DB אחת:
1. עדכן את ה-`Quote` הזו: `status = APPROVED`, `decidedAt = now()` — **רק אם**
   `status` הנוכחי הוא `PENDING_DECISION` (guard נגד double-submit: שני טאבים
   שמאשרים בו-זמנית). אם 0 שורות עודכנו → שגיאה "כבר הוכרע" למשתמש.
2. עדכן את **כל** ה-`Quote` האחרות באותה `Request` שעדיין `PENDING_DECISION`:
   `status = REJECTED`, `rejectedAuto = true`, `decidedAt = now()`.
3. שלח מייל למרפאה שאושרה ("המטופל בחר בכם") ולכל מרפאה שנדחתה אוטומטית
   ("המטופל בחר במרפאה אחרת") — ראו §4.

## 3.2 מטופל דוחה הצעה (עצמאי)

זהה לצעד 1 לעיל, על הצעה בודדת: `status = REJECTED`, `rejectedAuto = false`,
`decidedAt = now()`, guard על `PENDING_DECISION` הנוכחי. מייל למרפאה.

## 3.3 מרפאה מסמנת "הטיפול החל"

**מאמת:** המשתמש המחובר הוא בעל המרפאה (`getClinicForCurrentUser()`, אותו
מנגנון מ-PR #2), וה-`Quote` שייכת לאותה מרפאה.
**Guard:** רק אם `status === APPROVED`. עדכון ל-`IN_TREATMENT`,
`treatmentStartedAt = now()`. מייל למטופל.

## 3.4 מרפאה מבקשת אישור סיום

**Guard:** רק אם `status === IN_TREATMENT`. עדכון ל-`COMPLETION_REQUESTED`,
`completionRequestedAt = now()`. מייל למטופל עם קריאה לפעולה לאשר.

## 3.5 מטופל מאשר סיום

**מאמת:** בעל ה-`Request`. **Guard:** רק אם `status === COMPLETION_REQUESTED`.
עדכון ל-`COMPLETED`, `completedAt = now()`. מייל למרפאה.

## 3.6 נעילת עריכה

`submitQuote` (הפעולה הקיימת ב-`src/server/quotes.ts`) עושה `upsert` בלי שום
בדיקת מצב היום — מרפאה יכולה לערוך הצעה קיימת בלי הגבלה. **מ-הרגע שיש הכרעה
(`status !== PENDING_DECISION`), `submitQuote` חייבת לסרב לעדכון** ולהחזיר
שגיאה. דף `/quote/[token]` מציג טופס עריכה רק כש-`PENDING_DECISION` (או אין
`Quote` עדיין); בכל סטטוס אחר הוא הופך לתצוגת סטטוס בלבד — כולל להצעות
שנדחו, שצריכות עדיין להראות משהו קריא ("המטופל בחר במרפאה אחרת") ולא טופס
פתוח שנראה כמו תקלה.

# 4. מיילים

שישה מעברים, שישה מיילים, אותו דפוס retry-safe שכבר קיים
(`Quote.patientNotifiedAt` + קרון יומי שמנסה שוב מיילים שנכשלו):

| מעבר | נמען | חותמת שליחה |
|---|---|---|
| הצעה חדשה (קיים) | מטופל | `patientNotifiedAt` |
| אישור | מרפאה שאושרה | `decisionNotifiedAt` |
| דחייה (מפורשת או אוטומטית) | מרפאה שנדחתה | `decisionNotifiedAt` |
| הטיפול החל | מטופל | `treatmentStartedNotifiedAt` |
| בקשת אישור סיום | מטופל | `completionRequestedNotifiedAt` |
| אישור סיום | מרפאה | `completedNotifiedAt` |

הקרון היומי הקיים (שמטפל היום רק ב-`patientNotifiedAt IS NULL`) מורחב לבדוק
את כל חמש העמודות החדשות ולנסות שוב. תבניות מייל חדשות ב-
`src/server/emails/templates.ts`, אותו מבנה כמו `newQuoteEmailHtml`.

# 5. תצוגה — מטופל (`request/[id]`)

טבלת ההשוואה הקיימת (`QuoteComparison`) מקבלת עמודת פעולה/סטטוס לכל שורה:

- `PENDING_DECISION`: כפתורי "אשר" ו"דחה".
- `APPROVED`: תגית "אישרת ✓", מודגשת/מוצמדת לראש הטבלה.
- `REJECTED`: תגית "נדחתה", השורה מוצללת (עדיין גלויה — לא נעלמת).
- `IN_TREATMENT`: תגית "בטיפול".
- `COMPLETION_REQUESTED`: תגית + כפתור "אשר שהטיפול הסתיים".
- `COMPLETED`: תגית "הסתיים בהצלחה ✓".

אין `Quote` עדיין: כמו היום — "נשלח, ממתין למענה".

# 6. תצוגה — מרפאה (`clinics/dashboard`)

הליד הבינארי הקיים ("quoted"/"awaiting", `dashLeadQuoted`/`dashLeadAwaiting`
ב-`src/app/[locale]/clinics/dashboard/page.tsx`) מוחלף בתגית סטטוס מלאה +
כפתור פעולה מותנה:

| Status | תגית | כפתור |
|---|---|---|
| (אין quote) | ממתין למענה | — (קישור לטופס הצעה, כמו היום) |
| `PENDING_DECISION` | נשלחה, ממתין לתשובה | — |
| `APPROVED` | אושרה ✓ | "סמן שהטיפול החל" |
| `REJECTED` | נדחתה | — |
| `IN_TREATMENT` | בטיפול | "בקש אישור סיום" |
| `COMPLETION_REQUESTED` | ממתין לאישור המטופל | — |
| `COMPLETED` | הושלם בהצלחה ✓ | — |

השאילתה שמביאה את ה-`leads` (כרגע `select: { id, quote: { select: { id } } }`)
מורחבת ל-`quote.status`.

# 7. מקרי קצה

- **מרוץ אישור כפול** (שני טאבים, שתי בקשות "אשר" בו-זמנית על אותה הצעה, או
  אישור שתי הצעות שונות כמעט יחד): ה-guard `WHERE status = PENDING_DECISION`
  בעדכון עצמו הוא ההגנה — עדכון שמשפיע על 0 שורות מוחזר כשגיאה "כבר הוכרע",
  לא נכשל בשקט.
- **מרפאה שנדחתה מנסה לפתוח את `/quote/[token]` שלה**: מקבלת תצוגת סטטוס
  read-only ("המטופל בחר במרפאה אחרת"), לא טופס עריכה ולא 404.
- **בקשה שנמחקת** (`DeleteRequestButton` הקיים) אחרי שהיא כבר `SENT` — לא
  קשור למחזור החיים הזה; מחיקה מוחקת קסקדינג את כל ה-`RequestDentist`/`Quote`
  שלה כמו היום.

# 8. מחוץ להיקף (v1)

- ביטול/חזרה מהחלטה (§1.4).
- הצעות מרובות-גרסאות / היסטוריית מחיר.
- תזכורת אוטומטית אם המטופל לא מגיב להצעה או לבקשת אישור סיום.
- תשלום/הזמנה בפועל דרך האתר — עדיין P3 בפני עצמו, לא קשור למחזור החיים
  הזה.
- ערעור על "הושלם" מצד המרפאה אם המטופל לא מאשר (מקרה קצה לתמיכה אנושית).

# 9. חלוקה מוצעת

1. **מודל + מיגרציה**: `QuoteStatus`, שדות חדשים על `Quote`. בדיקות סכימה.
2. **פעולות שרת**: אישור, דחייה, סימון בטיפול, בקשת סיום, אישור סיום — כל אחת
   עם ה-guard וה-authorization שלה. בדיקות אינטגרציה לכל מעבר + למרוץ הכפול.
3. **נעילת `submitQuote`** לפי סטטוס + עדכון `/quote/[token]` לתצוגת read-only
   מתאימה.
4. **מיילים**: חמש תבניות חדשות + הרחבת הקרון היומי לחמש העמודות החדשות.
5. **UI מטופל**: כפתורי פעולה + תגיות ב-`QuoteComparison`.
6. **UI מרפאה**: תגיות + כפתורי פעולה בדשבורד, הרחבת השאילתה.
7. **אימות סופי**: מעבר ידני מקצה לקצה (מצטרף לרשימת המעברים הידניים הקיימת
   שממתינה לאדן).
