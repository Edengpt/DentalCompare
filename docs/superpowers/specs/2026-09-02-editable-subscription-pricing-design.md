# 0. הבעיה

`SUBSCRIPTION_PLANS` ו-`TRIAL_DAYS` ב-`src/lib/constants.ts` הם קבועים
בקוד: 299₪/1990₪ ו-60 יום. כל שינוי מחיר או אורך ניסיון דורש דיפלוי. זה
חוסם שתי מטרות: (1) גמישות עסקית — אדן רוצה לשנות ערכים בלי לגעת בקוד;
(2) תת-פרויקט ב' (Stripe למרפאות מחוץ לישראל) יצטרך מחיר/ניסיון נפרדים
במטבע אחר, וזה בדיוק אותה בעיה פעמיים.

# 1. החלטות סגורות

התקבלו בליבון מול אדן ב-2026-09-02.

## 1.1 שני "מסלולים" נפרדים, לא הרחבה של מנגנון אחד

מחיר וניסיון הם **לפי ספק תשלומים**, לא ערך גלובלי יחיד: PayPlus (ישראל,
ILS) ו-Stripe (שאר העולם, USD — תת-פרויקט ב') — כל אחד עם מחיר חודשי, מחיר
שנתי, וימי ניסיון משלו. זה כולל את **המסלול הישראלי הקיים**, לא רק את מה
שעדיין לא נבנה — אדן ביקש זאת במפורש אחרי שהוצג לו שהתכנון המקורי כלל רק
את המסלול הבינלאומי.

## 1.2 מטבע קבוע לכל ספק, לא ניתן לעריכה

`currency` נשמר בשורה (ILS ל-PayPlus, USD ל-Stripe) לצורך התבנית „minor
units + currency" הקיימת בכל מקום בקוד, אבל **לא חשוף לעריכה במסך
האדמין** — שינוי מטבע לספק קיים הוא שינוי מבני, לא כוונון מחיר.

## 1.3 שינוי משפיע על הרשמות חדשות בלבד

מרפאה ששומרת שורת `ClinicSubscription` משלה (`priceMinor`/`currency`
ישירות על השורה, לא מחושבים מחדש) שומרת את המחיר שקיבלה בזמן ההרשמה —
בדיוק כמו שהמנגנון כבר עובד היום. שינוי בהגדרה משפיע רק על הרשמה הבאה
שקוראת את השורה. אין backfill, אין "עדכון רטרואקטיבי".

## 1.4 תת-פרויקט א' לא בונה את Stripe עצמו

המסך, המודל, ופעולת העדכון תומכים בשני הספקים באותה צורה, אבל **אף מסלול
הרשמה חדש לא נבנה כאן**. שורת ה-`STRIPE` נזרעת עם ערכי ברירת מחדל
($79/$530/60) ומחכה לתת-פרויקט ב' — עד אז היא קיימת במסד ובמסך האדמין,
לא בשימוש בפועל.

# 2. המודל

```prisma
enum SubscriptionProvider {
  PAYPLUS
  STRIPE
}

model SubscriptionPricing {
  provider          SubscriptionProvider @id
  currency          String   // ILS | USD — לא ניתן לעריכה ב-UI
  monthlyPriceMinor Int
  yearlyPriceMinor  Int
  trialDays         Int
  updatedAt         DateTime @updatedAt
  updatedBy         String?  // אימייל האדמין שערך לאחרונה
}
```

מיגרציה אחת, עם שתי שורות זרע:

| provider | currency | monthlyPriceMinor | yearlyPriceMinor | trialDays |
|---|---|---|---|---|
| `PAYPLUS` | `ILS` | 29900 | 199000 | 60 |
| `STRIPE` | `USD` | 7900 | 53000 | 60 |

שורת `PAYPLUS` היא **בדיוק** הערכים החיים היום ב-`SUBSCRIPTION_PLANS`/
`TRIAL_DAYS` — שום דבר לא זז בפועל למרפאה קיימת או חדשה ברגע הדפלוי.

**עקרון מכריע (כמו בכל מסמך עיצוב אחרון בפרויקט הזה):** קריאה לפי
`provider` היא הדרך היחידה לקבל מחיר/ניסיון. אין חישוב מקומי חוזר, אין
קבוע שממשיך לחיות במקביל לשורה במסד.

# 3. מה זז — עשרה מקומות

כל אחד מהקבצים הבאים מייבא היום `SUBSCRIPTION_PLANS` ו/או `TRIAL_DAYS`
מ-`@/lib/constants` ועובר לקרוא את שורת ה-`PAYPLUS` מהמסד (זו היחידה
בשימוש בפועל כרגע — אין עדיין הרשמה שמובילה ל-`STRIPE`):

1. `src/lib/subscription.ts` — `trialEndsAt`, `nextPeriodEnd` (קומפוננטות
   טהורות; יקבלו את הערכים כפרמטר במקום לייבא קבוע).
2. `src/server/subscriptions.ts` — יוצר `ClinicSubscription` חדשה.
3. `src/server/admin-actions.ts` — יצירת מרפאה במסלול הידני
   (`createDentist`).
4. `src/app/api/cron/renew-subscriptions/route.ts` — כבר קורא
   `priceMinor`/`currency` מהשורה הקיימת של המנוי, לא מהקבוע ישירות; רק
   נקודת המקור של הקבוע עצמו (למרפאה חדשה) זזה.
5. `src/app/[locale]/clinics/billing/[token]/page.tsx`.
6. `src/components/clinics/plan-picker.tsx` — **"use client"**, יקבל
   מחירים כ-props.
7. `src/components/clinics/registration-form.tsx` — **"use client"**,
   יקבל מחירים ו-`trialDays` כ-props.
8. `src/app/[locale]/clinics/join/page.tsx` — קומפוננטת שרת שמרנדרת את
   שתי הקומפוננטות למעלה; קוראת את המסד וממררת props.
9. `src/app/[locale]/refunds/content.he.tsx` / `content.en.tsx`.
10. `src/app/[locale]/terms/content.he.tsx` / `content.en.tsx`.

עמודי החוקיים (9-10) כבר קומפוננטות שרת — עוברים לקרוא את המסד ישירות
באותה נקודה שבה הם כבר מרכיבים את תבנית `SITE_CONFIG`/`formatMoney`
הקיימת. שום שינוי בניסוח המשפט עצמו, רק במקור הערך.

`SUBSCRIPTION_PLANS`/`TRIAL_DAYS` **נמחקים** מ-`src/lib/constants.ts` אחרי
שכל עשרת המקומות זזו — אין להשאיר קבוע מת לצד המסד (זו בדיוק המשפחה של
הבאג שכבר תועדה כמה פעמים במסמכים האלה: שני מקורות אמת לאותה עובדה).

# 4. פעולת העדכון והמסך

## 4.1 `updatePricing`

```ts
async function updatePricing(
  provider: "PAYPLUS" | "STRIPE",
  input: { monthlyPriceMinor: number; yearlyPriceMinor: number; trialDays: number },
): Promise<ActionResult>
```

`requireAdmin()` (הדפוס הקיים ב-`src/server/admin.ts`) בתחילת הפעולה.
ולידציה: שלושת המספרים שלמים וחיוביים; `trialDays` בטווח סביר (1-365,
כדי לתפוס הקלדה שגויה כמו "6000" בלי לקבוע כלל עסקי שרירותי מעבר לזה).
כתיבה ל-`audit()` עם `actor: admin.email`, `metadata` שכולל את הערכים
הישנים והחדשים — כדי שסטייה במחיר תהיה ניתנת לחקירה, לא רק ניתנת לצפייה
כרגע.

## 4.2 המסך

פאנל עריכה חדש בראש מסך „מנויים" הקיים באדמין (`/[locale]/admin/subscriptions`)
— לא מסך נפרד. שתי שורות (PayPlus, Stripe), כל אחת: מחיר חודשי, מחיר
שנתי, ימי ניסיון, ותאריך/מי עדכן לאחרונה. שדה המטבע מוצג לקריאה בלבד.

# 5. מחוץ להיקף (תת-פרויקט א')

- כל דבר שקשור בפועל ל-Stripe — checkout, webhooks, בחירת ספק לפי מדינת
  מרפאה, `ClinicSubscription.provider`. זה תת-פרויקט ב'.
- וריסיון/היסטוריית מחירים (מה היה המחיר בתאריך X). `updatedAt`/`updatedBy`
  נותנים רק את המצב האחרון.
- שינוי רטרואקטיבי על מנויים קיימים.
