# P0 — תשתית בינלאומית (International Foundations)

- **תאריך:** 2026-08-20
- **סטטוס:** מאושר לתכנון יישום
- **שלב:** P0 מתוך P0–P5

---

# 1. Background

DentalCompare נבנתה כמרקטפלייס ישראלי מקומי: מטופל ומרפאה באותה מדינה, באותו
מטבע, תחת אותו רגולטור. ההחלטה מ-2026-08-20 היא להפוך אותה למרקטפלייס
**תיירות מרפא חוצה-גבולות** — מטופל בלונדון משווה הצעות מבודפשט, מאיסטנבול
ומתל אביב, והפער בין המדינות הוא המוצר עצמו.

## 1.1 העיקרון המנחה

**מדינה היא נתון, לא קוד.** להוסיף את מקסיקו למערכת חייבת להיות פעולת אדמין
בממשק — שורה בטבלה — ולא גרסה חדשה של האתר. שום רשימת מדינות לא תיכתב קשיח
בקוד שוב.

## 1.2 מה חוסם את זה היום

ישראל אינה *מוגדרת* במערכת, היא **מקודדת קשיח** לתוכה:

| # | הממצא | המיקום | ההשלכה |
|---|---|---|---|
| 1 | טלפון לא-ישראלי נדחה | `src/lib/phone.ts:36` | מרפאה או מטופל מחו"ל **לא יכולים להירשם כלל** |
| 2 | סליקה ישראלית בלבד | `src/lib/payplus.ts` (252 שורות) | מרפאה זרה לא יכולה לשלם מנוי |
| 3 | המטבע חרוט בסכמה | `amountILS`, `priceILS`; ~222 מופעי ILS/₪ | אי אפשר לייצג הצעה ביורו |
| 4 | קופות חולים ישראליות | `HMO_OPTIONS` ב-`constants.ts` | שדה חובה חסר משמעות מחוץ לישראל |
| 5 | אין מדינה במודל | `Dentist.city` בלבד | אין שום היגיון גאוגרפי בהתאמה |
| 6 | רישוי ישראלי בתנאים | `SUBSCRIPTION_TERMS_HE` | תנאי המנוי דורשים רישיון **בישראל** |
| 7 | אין GDPR | — | צילומי רנטגן ותוכניות טיפול הם נתוני בריאות (Article 9) |

P0 מטפל ב-1, 3, 4, 5 ומוסיף את שכבת השפות ומודל המדינות. פריטים 2, 6, 7
שייכים ל-P3 ול-P4.

# 2. Scope

## 2.1 בתוך ההיקף

1. `Country` — מודל מדינה מונע-נתונים
2. טלפון בינלאומי (מחליף את `normalizeIsraeliMobile`)
3. כסף רב-מטבעי (`amountMinor` + `currency`) ושערי חליפין
4. מבטחים לפי מדינה (מחליף את `HMO_OPTIONS`)
5. שדות ההשוואה החדשים ב-`Quote`
6. שכבת שפות (`/he`, `/en`, מוכנה ל-N שפות)
7. `middleware.ts` עטוף ב-`clerkMiddleware()`

## 2.2 מחוץ להיקף (מכוון)

| נדחה ל- | מה |
|---|---|
| P1 | ממשק ההשוואה החוצה-גבולות, מדינת מוצא של המטופל, יסודות GDPR |
| P2 | תהליך אימות הרישיונות, הסמכות, ביקורות מאומתות |
| P3 | Stripe, תמחור מנוי לפי שוק, מע"מ וחשבוניות |
| P5 | SEO לכל שוק, אסטרטגיית דומיין, דוחות רב-מטבעיים |

## 2.3 החלטות YAGNI מפורשות

- **אין חישוב אוטומטי של עלות טיסה.** דורש חיבור למאגרי טיסות, המחירים משתנים
  שעה-שעה, וטעות הורסת אמון. במקום זה: "2 נסיעות · 5 ימים כל אחת" מוצג בבירור,
  והמטופל מוסיף את החשבון שלו.
- **אין גאוקודינג ואין חישוב מרחקים.** `city` נשאר טקסט חופשי. מדינה מספיקה
  לסינון ב-P1.
- **אין תרגום אוטומטי של תוכן מהמסד.** שם מרפאה, כתובת והערת הצעת מחיר מוצגים
  כפי שנכתבו.

# 3. Architecture

## 3.1 מודל המדינה

```prisma
model Country {
  code          String   @id              // ISO 3166-1 alpha-2: "IL", "TR", "HU"
  nameEn        String
  currency      String                    // ISO 4217: "ILS", "TRY", "EUR"
  callingCode   String                    // "972", "90", "36"
  defaultLocale String   @default("en")
  // מבטחים לתצוגה בפרופיל המרפאה. ריק במדינה שבה זה לא רלוונטי.
  insurers      String[]
  // אילו מסמכי רישוי האדמין חייב לראות לפני אישור מרפאה. P2 משתמש בזה;
  // P0 רק מאחסן, כדי שהמודל לא ישתנה שוב.
  requiredDocs  String[]
  isActive      Boolean  @default(false)
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt

  dentists Dentist[]
  users    User[]
}
```

`isActive` מוגדר `false` כברירת מחדל **בכוונה**: מדינה חדשה נכנסת כטיוטה,
והאדמין מפעיל אותה רק אחרי שמילא מטבע, מבטחים ומסמכים נדרשים. מדינה חצי-מוגדרת
לא תופיע למשתמשים.

## 3.2 טלפון בינלאומי

`src/lib/phone.ts` מחליף את `normalizeIsraeliMobile` ב-`normalizePhone(input, countryCode)`
מעל `libphonenumber-js`.

- מחזיר E.164 או `null`, בדיוק כמו החתימה הקיימת — הקוראים לא משתנים במבנה.
- `countryCode` משמש כרמז לפרשנות מספר מקומי (`05X…` → `+9725X…`,
  `07X…` בבריטניה → `+447X…`). מספר שכבר בפורמט בינלאומי מנצח את הרמז.
- **כל הבדיקות הקיימות למספרים ישראליים נשארות ועוברות ללא שינוי.** ישראל
  מפסיקה להיות המקרה היחיד; היא לא מפסיקה לעבוד.

`libphonenumber-js` נבחרה על פני `libphonenumber` המלאה: ~145KB לעומת ~530KB,
והפונקציונליות הנדרשת (parse, validate, format) זהה.

## 3.3 כסף

### הייצוג

כל סכום נשמר כזוג: `<name>Minor Int` + `currency String`.

`Minor` = היחידה הקטנה של המטבע (אגורות, סנטים, קורושים). **שמירה כמספר שלם
ביחידה הקטנה היא הדרך היחידה למנוע שגיאות עיגול בכסף** — `float` על סכומים
כספיים צובר סטייה, ו-`Decimal` מסבך את הסליקה ללא תועלת כאן.

הערה: לא כל מטבע הוא בן 100 יחידות (JPY בן 1, KWD בן 1000). מספר הספרות נגזר
מ-`Intl.NumberFormat` ולא מקבוע 100.

### שערי חליפין

```prisma
model ExchangeRate {
  base      String                        // "EUR"
  quote     String                        // "ILS"
  rate      Decimal  @db.Decimal(18, 8)
  fetchedAt DateTime

  @@id([base, quote])
}
```

נשלף פעם ביום ב-cron **חדש** (`src/app/api/cron/refresh-exchange-rates`), לצד
שלושת ה-cron הקיימים ובאותה תבנית אימות `CRON_SECRET`. לא מוטמע באחד הקיימים:
כישלון משיכת שערים לא אמור להכשיל חידוש מנויים.

**ההצעה נשמרת תמיד במטבע שהמרפאה נקבה בו** — ההמרה היא
תצוגה בלבד, מלווה בתווית "שער להיום". שמירת סכום מומר תיצור התחייבות למחיר
שאין עליו שליטה.

אם שער חסר או ישן מ-48 שעות: מוצג הסכום במטבע המקורי בלבד, ללא המרה, ובלי
שגיאה למשתמש. **המרה שקטה בשער ישן גרועה מאי-המרה.**

## 3.4 מבטחים

`HMO_OPTIONS` יורד מ-`constants.ts`. `Dentist.hmoAffiliations` משתנה שמו
ל-`insurerAffiliations`, והערכים המותרים נגזרים מ-`Country.insurers` של מדינת
המרפאה.

לישראל: `["Clalit", "Maccabi", "Meuhedet", "Leumit"]` — אותם ערכים בדיוק,
אותן תוויות עבריות ב-`labels.ts`. **אף מרפאה ישראלית קיימת לא מאבדת נתון.**

## 3.5 שדות ההשוואה ב-Quote

היום `Quote` מכיל `amountILS` והערה חופשית. זה מספיק להשוואת שלוש מרפאות בתל
אביב ולא מספיק בין מדינות, כי **המחיר לבדו משקר**: הצעה של £3,200 בשתי נסיעות
יקרה יותר מהצעה של £4,000 בנסיעה אחת.

```prisma
// --- הוספות ל-Quote ---
amountMinor       Int
currency          String

// מה כלול. מפתחות קנוניים; התוויות בשכבת השפות.
// XRAYS | ANESTHESIA | TEMP_CROWN | FOLLOW_UP | AIRPORT_TRANSFER | ACCOMMODATION
includes          String[]

// נסיעות — הנתון שמזיז הכי הרבה את העלות האמיתית
tripsRequired     Int      @default(1)
daysPerTrip       Int
weeksBetweenTrips Int?     // null כשנדרשת נסיעה אחת

// אחריות — החשש הגדול ביותר של מטופל תיירות מרפא
warrantyYears     Int?
warrantyNote      String?  @db.Text
```

**שפות הצוות יושבות על `Dentist`, לא על `Quote`** (`spokenLanguages String[]`):
הן מאפיין של המרפאה ואינן משתנות בין הצעה להצעה. שכפולן לכל הצעה היה מייצר
סתירות.

## 3.6 שכבת השפות

```
src/i18n/
  config.ts           locales, defaultLocale, dir map, isLocale()
  dictionaries/he.ts  ← מקור האמת
  dictionaries/en.ts  ← const en: typeof he = { … }
  get-dictionary.ts   getDictionary(locale) — server only
  provider.tsx        I18nProvider + useT() — ל-21 קומפוננטות הלקוח
```

- `src/app/[locale]/` מקבל את 27 העמודים. `src/app/api/` נשאר בשורש.
- **`en.ts` מוגדר `typeof he` — הבנייה נכשלת אם חסר מפתח.** זו ההגנה היחידה
  שמונעת אתר חצי-מתורגם, והיא הסיבה לבחור מילונים ידניים על פני ספרייה.
- קומפוננטות שרת: `const t = await getDictionary(locale)`.
- קומפוננטות לקוח: `I18nProvider` מעביר **רק את המרחב הנדרש** מהמילון שכבר
  נטען בשרת. השפה השנייה לא נשלחת ללקוח כלל.
- המילון מחולק למרחבים: `hero`, `howItWorks`, `faq`, `request`, `clinics`,
  `admin`, `errors`, `common`.
- הוספת שפה = קובץ מילון חדש + שורה ב-`config.ts`. המבנה מוכן ל-N שפות מראש,
  כי גרמנית וטורקית יגיעו.

### כיווניות

הקוד כבר כמעט נקי — רק שלושה קבצים משתמשים במחלקות כיווניות
(`request/[id]/page.tsx:158`, `legal/legal-layout.tsx:61`,
`request/explain-treatment.tsx:102`). מתוקנים ל-`me-2` / `ps-5` / `border-s-2`.

הבעיה האמיתית היא `ArrowLeft` המשמש ב-10 מקומות כחץ "קדימה" — נכון בעברית,
**הפוך באנגלית**, יחד עם `group-hover:-translate-x-1`. פתרון: קומפוננטה אחת
`<ForwardArrow />` ב-`components/ui` שבוחרת אייקון וכיוון תנועה לפי ה-locale.

## 3.7 Middleware — הסיכון הגבוה ביותר בשלב

**היום אין `src/middleware.ts` בפרויקט כלל**, ו-Clerk עובד דרך `auth()` ישירות
בקומפוננטות שרת. הוספת middleware משנה את צינור הבקשות; אם הוא לא עטוף
ב-`clerkMiddleware()`, **ה-auth נשבר בשקט** — בלי שגיאה, בלי כשל בבנייה.

```ts
export default clerkMiddleware((auth, req) => {
  // /api, /_next, /monitoring וכל נתיב עם סיומת קובץ — עוברים ללא נגיעה
  // נתיב שמתחיל ב-locale נתמך — קובע cookie וממשיך
  // נתיב שמתחיל בסגמנט דמוי-locale שאינו נתמך (/de/…) — 404, ללא הפניה
  // אחרת — הפניה ל-/<negotiated>/<path>
});
```

זיהוי שפה: cookie `NEXT_LOCALE` → כותרת `Accept-Language` → `he`.

**הבחנה שקובעת התנהגות:** סגמנט ראשון בן שתי אותיות שנראה כמו קוד שפה אך אינו
נתמך (`/de/request`) מקבל **404**, ולא הפניה ל-`/he/de/request`. הפניה במקרה
כזה הייתה מייצרת 404 מטעה בכתובת אחרת ומסתירה קישור שבור. סגמנט שאינו דמוי-שפה
(`/request`) מופנה כרגיל.

**סדר עבודה מחייב:** ה-middleware נכתב ראשון, ובדיקת התחברות ידנית מלאה
(הרשמה, כניסה, יציאה, גישה לעמוד מוגן) מאומתת **לפני** כל שינוי אחר בשלב.

# 4. Data Model — סיכום השינויים

| מודל | שינוי |
|---|---|
| `Country` | **חדש** |

# 5. Migration Strategy

מיגרציית הכסף נוגעת בסליקה, בחיובים החוזרים ובדוחות, ויש בטבלאות נתונים אמיתיים.
לכן היא **מפוצלת לארבעה שלבים הפיכים**, לא לשינוי אחד:

| שלב | פעולה | הפיך? |
|---|---|---|
| M1 | הוספת העמודות החדשות כ-nullable. הישנות נשארות. | כן — מחיקת עמודה ריקה |
| M2 | Backfill: `amountMinor = amountILS * 100`, `currency = 'ILS'` | כן — העמודה הישנה שלמה |
| M3 | העברת כל הקריאות והכתיבות לעמודות החדשות; הישנות הופכות ל-read-only | כן — חזרה לקוד הקודם |
| M4 | הפיכת החדשות ל-`NOT NULL`, מחיקת הישנות | לא — **רק אחרי שבוע יציב בפרודקשן** |

**דורש אימות לפני M2:** האם `amountILS` מייצג שקלים שלמים או אגורות. הקבועים
(`priceILS: 299`, `priceILS: 1990`) והתצוגה (`{s.priceILS} ₪`) מצביעים על שקלים
שלמים, אבל **מה ש-`payplus.ts` שולח בפועל לסליקה הוא הקובע** ויש לוודא אותו
בקוד לפני כתיבת ה-backfill. טעות כאן היא פי 100 בחיוב אמיתי.

מיגרציות נוספות, פשוטות יותר:

- `countryCode` נוסף עם `@default("IL")` — כל השורות הקיימות נכונות מיידית.
- `hmoAffiliations` → `insurerAffiliations`: שינוי שם עמודה, הנתונים זהים.
- ה-seed של `Country` מכניס את ישראל כשורה פעילה ראשונה.

# 6. Error Handling

| מצב | התנהגות |
|---|---|
| שער חליפין חסר או ישן מ-48 שעות | הצגת הסכום המקורי בלבד, ללא המרה, ללא שגיאה למשתמש |
| מדינה לא פעילה (`isActive=false`) | לא מופיעה בטפסים ולא בסינון; מרפאות קיימות בה נשארות במסד |
| טלפון שלא ניתן לפרש | `null` — בדיוק ההתנהגות הקיימת. אימות טלפון הוא נדנוד ולא שער (`996dea7`) |
| `locale` לא מוכר ב-URL | 404, לא הפניה שקטה — הפניה מסתירה שגיאות קישור |
| מפתח חסר במילון | לא ייתכן בזמן ריצה: `typeof he` מפיל את הבנייה |

# 8. Rollout Order

הסדר אינו שרירותי — כל שלב חוסם את הבא:

1. **`middleware.ts` + אימות Clerk ידני.** אם זה נשבר, כל השאר לא רלוונטי.
2. **טלפון בינלאומי.** הבאג שחוסם רישום זר; בלעדיו אי אפשר לבדוק שום דבר
   בינלאומי מקצה לקצה.
3. **`Country` + `ExchangeRate` + seed של ישראל.**
4. **מיגרציית הכסף M1–M3.**
5. **מבטחים לפי מדינה.**
6. **שדות ההשוואה ב-`Quote`.**
7. **שכבת השפות ו-`[locale]/`.**
8. **M4** — רק אחרי שבוע יציב בפרודקשן.

# 9. Known Limitations

מוסכם מראש, לא ליקויים שנתגלו:

1. **P0 לא משנה דבר שנראה באתר.** הוא מסיר חסמים; הפיצ'ר הנראה לעין מגיע ב-P1.
2. **מרפאה זרה עדיין לא יכולה לשלם.** PayPlus הוא P3. מכוון: בשלב הראשון עדיף
   לגייס מרפאות זרות בחינם — אין עדיין ביקוש שמצדיק מנוי, וצריך היצע לפני
   שיש למי להציע.
3. **GDPR עדיין לא מיושם.** חייב לנחות **יחד עם** P1 ולא אחריו — ברגע שהמטופל
   האירופי הראשון מעלה צילום רנטגן, כבר מאוחר.
4. **תנאי המנוי עדיין דורשים רישיון ישראלי.** P4.
5. **אין היגיון גאוגרפי מעבר למדינה.** מספיק ל-P1; מרחק וזמן טיסה נדחים.
