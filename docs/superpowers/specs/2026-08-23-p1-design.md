# 1. החלטות סגורות

התקבלו בליבון מול אדן ב-2026-08-23. **שתיים מהן התהפכו תוך כדי, וההיפוך מכוון**
— מי שקורא את זה בסשן חדש, אל תציע לחזור לגרסה הראשונה.

## 1.1 שני כיווני נסיעה, סימטרית

לא "ישראלי שטס לחו״ל" ולא "זר שטס לישראל" — **המערכת לא מניחה כיוון.** נאמן
ל-P0, שנבנה סימטרי בכוונה; לבנות את P1 עם כיוון מובנה היה מבטל את זה.

**מה זה פוסל:** כל עיצוב שממסגר את המסע כולו סביב טיסה. זו הסיבה שגישת
„מסלול שמתחיל מהיעד” נדחתה — היא מענישה מטופל שרק רוצה כתר ברעננה.

## 1.2 מדינת המטופל נשאלת במפורש

שדה בורר, **ממולא מראש** לפי קידומת הטלפון שכבר נמסרה. לרוב לחיצה אחת.

**למה לא להסיק בשקט:** ישראלי שגר בלונדון מחזיק מספר ישראלי. ניחוש שגוי כאן
אינו אי-נוחות — הוא קובע באיזה מטבע מוצגים מחירים ואיזה משטר פרטיות חל.

## 1.3 שאלה מפורשת „מוכנים לטוס?”, לפני בחירת המרפאות

**לא** פילטר מדינה חבוי במאגר. הנימוק דו-כיווני: מי שרצתה כתר ברעננה לא צריכה
רשימה מעורבבת מארבע מדינות, ומי שכן היה טס לא יגלה שזו אפשרות אם היא מסתתרת
מאחורי פילטר.

## 1.4 אירופה **בפנים** ב-P1 — עם הסכמה, שקיפות ו-SCCs

**זו ההחלטה שהתהפכה, ובכוונה.** תחילה נבחר „אירופה מחוץ ל-P1”. שני דברים
שינו אותה:

1. **הונגריה, פולין ורומניה חברות באיחוד.** בודפשט היא בירת תיירות השיניים של
   אירופה. „בלי אירופה” היה מוריד את היעדים המרכזיים ומשאיר בעיקר את טורקיה.
   בריטניה — שהיא שוק המקור הגדול ביותר — נושאת GDPR משלה, כך שגם היא נופלת.
2. **אדן תיקן נקודה מהותית ונכונה:** GDPR **אינו** דורש לוקליזציה של נתונים.
   העברה לארה״ב חוקית עם מנגנון העברה תקף (SCCs / Data Privacy Framework),
   הסכמי עיבוד מול הספקים והצהרה מפורשת במדיניות הפרטיות. הצגת המעבר לאירופה
   כ„דרך הנקייה” הייתה הטיה שלי; היא אחת מכמה דרכים, ולא הזולה.

**לכן: התשתית נשארת בארה״ב.** מה שנדרש הוא שקיפות והסכמה — פרק 6.

> **עובדה שאומתה ולא הייתה ידועה:** `X-Vercel-Id: fra1::iad1` — הבקשות נכנסות
> דרך פרנקפורט אבל **הקוד רץ ב-iad1, וירג'יניה**. זו ברירת המחדל של Vercel ואף
> אחד לא בחר בה. אזור ה-Neon לא נבדק — `DATABASE_URL` מסומן Sensitive ולא ניתן
> לקריאה חוזרת.

## 1.5 הגישה שנבחרה: „פרוסה דקה + טבלת השוואה”

מבין שלוש שהוצגו. הנדחות: „פרוסה דקה בלבד” (משאירה את ההשוואה כערימת כרטיסים
— בדיוק הבעיה שהמוצר קיים כדי לפתור) ו„מסלול שמתחיל מהיעד” (סותרת את 1.1).

# 2. מה כבר בנוי ומחכה

P1 הוא במידה רבה **חיבור של מה שנבנה ב-P0 ואינו בשימוש**, ולא בנייה מאפס:

| נכס | מצב |
|---|---|
| `Quote.includes` / `tripsRequired` / `daysPerTrip` / `warrantyYears` | נאספים ומוצגים חלקית |
| `ExchangeRate` + קרון יומי + `convert()` + `isRateStale()` | **נכתבים, לא נקראים. אפס שימוש בממשק.** |
| `User.countryCode` | קיים, **תמיד "IL"** — אף אחד לא כותב אליו |
| `Dentist.spokenLanguages` | חוּוט ב-2026-08-23 (טופס, כרטיס, אדמין) |
| `Country` + מסך אדמין | פעיל |

# 3. מדינת המטופל ומרחק הנכונות

המסלול היום: העלאה ← בחירת מרפאות ← אישור ← נשלח. **נכנס שלב אחד בין ההעלאה
לבחירה**, ובו שתי שאלות.

```prisma
enum TravelScope {
  LOCAL     // רק במדינה שלי
  SELECTED  // מדינות שנבחרו
  ANY       // כל מדינה פעילה
}

model Request {
  travelScope         TravelScope @default(LOCAL)
  destinationCountries String[]   // בשימוש רק כאשר SELECTED
}
```

**למה על הבקשה ולא על המשתמש:** אותו אדם יטוס בשביל שתי השתלות ולא בשביל
סתימה. זו תכונה של הטיפול, לא של האדם.

**למה enum ולא רק רשימה:** „לכל מקום” חייב להיות *„כל מדינה פעילה כרגע”* ולא
רשימה שהוקפאה ברגע הלחיצה. אחרת מדינה שתתווסף מחר לא תיכלל באף בקשה קיימת,
בשקט.

# 4. הגילוי

- המאגר מסונן לפי `travelScope` של הבקשה.
- **שני פילטרים חדשים: מדינה ושפה.** השפה היא השדה שחוּוט ב-23.8.
- **כרטיס המרפאה יציג מדינה.** היום עיר בלבד — „תל אביב” ו„בודפשט” זו לצד זו
  בלי מדינה היא רשימה מבלבלת.
- **תקרת 3 המרפאות נשארת.** החלטה עסקית על בלעדיות לידים; חציית גבולות אינה
  משנה את ההיגיון שלה.

---

# 5. טבלת ההשוואה

דף הבקשה עובר מערימת כרטיסים לטבלה: **מרפאה בכל עמודה, מימד בכל שורה** —
מחיר · מה כלול · נסיעות וימים · אחריות · שפות · מדינה ועיר.

שני כללים שקובעים אם היא כנה:

1. **חסר אינו אפס.** מרפאה שלא מילאה אחריות מציגה „לא צוין”, לא „0 שנים”.
   ההבדל הוא בין „אין אחריות” לבין „לא אמרו”, והראשון הוא האשמה.
2. **בטלפון הטבלה נגללת לצדדים בתוך עצמה**, והדף לא. שלוש עמודות במסך צר הן
   בלתי קריאות.

---

# 6. הכסף

- **ההצעה מוצגת תמיד במטבע שהמרפאה נקבה בו.** זו האמת וזה מה שישולם.
- לצדה **המרה מקורבת** למטבע המטופל, מסומנת כמקורבת ועם תאריך השער.
- **שער ישן מ-48 שעות — לא מוצגת המרה כלל.** `isRateStale()` נכתב בדיוק לזה
  ומעולם לא נקרא. מספר ישן שמוצג כעובדה גרוע ממספר שלא מוצג.
- מטבע המטופל נגזר מ-`Country.currency` של המדינה שבחר.
- **לעולם לא ממירים בשמירה** — עקרון מ-P0 §3.3 שנשאר בתוקף.

# 7. הסכמה, פרטיות ומחיקה

## 7.1 הסכמה מפורשת

תיבה **נפרדת מכל אישור אחר**, בשלב ההעלאה:

> „אני מאשר/ת שתוכנית הטיפול והצילום יישלחו למרפאות שאבחר, ויאוחסנו על שרתים
> בארצות הברית.”

נשמרים **התאריך וגרסת הנוסח** — אותה תבנית שכבר קיימת למרפאות
(`agreedToTermsAt` + `termsVersion`). אותו היגיון: להוכיח למה בדיוק הסכימו.

## 7.2 מדיניות פרטיות

מתעדכנת ואומרת במפורש היכן המידע יושב, מי הספקים ומה בסיס ההעברה.

⚠️ **הנוסח חייב אישור עורך דין.** אפשר לנסח טיוטה, לא לאשר אותה. מדובר במידע
בריאותי — הקטגוריה המוגנת ביותר.

## 7.3 מחיקה — פער שנמצא בליבון

**אין היום שום דרך שמטופל ימחק את המידע שלו, והקבצים בענן אינם נמחקים לעולם**
— גם לא כשחשבון Clerk נמחק (`user.deleted` רק מאפס `userId`). זכות המחיקה אינה
אופציונלית. P1 יכלול פעולת „מחקו את הבקשה שלי” שמוחקת גם את הקובץ מהאחסון.
